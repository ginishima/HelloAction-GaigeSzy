29. What is the purpose of the on section?
 - The "on" section dictates the trigger for when the workflow runs. It is not dissimilar to an "if" statement.
30. What does workflow_dispatch do?
 - Workflow dispatch is a sort of manual trigger set, it's saying "you can execute this workflow manually"
31. What does runs-on specify?
 - The "runs-on" specifies which runner/machine the workflow will execute on.
32. Why is actions/checkout needed?
 - "actions/checkout" is required for ensuring that the workflow is executed within the latest branh version.
33. What does the language setup action do?
 - language setups will install the runtime package managers natively
34. What is the difference between compiling and running the program?
 - Compiling is when the code is transferred into machine code, understandable by the computer to execute the specified functions. Running, is the execution of those actions.
35. Where can you see the program output?
 - The program output can be found on GitHub in the "actions" tab, then clicking on the program execution step of your completed workflow.
36. What is the difference between a workflow, a job, and a step?
 - Workflow is the entire process. A job is one of the actions the workflow must complete. Steps are the action within a job that a workflow/program must execute.
